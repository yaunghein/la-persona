# Auth: manual test guide

Signing in, signing out, and who can reach which area. La Persona has no passwords: every account signs in with a magic link, and the first link for an address creates the account.

Button and field labels come from the code. If one doesn't match the UI, update this guide.

This guide is the source for `tests/01.auth.test.ts`. Keep step numbers stable, and write every outcome as an **Expected** line that a test can assert. [Notes for e2e tests](#notes-for-e2e-tests) at the end covers what changes when a test runs a step instead of a person.

## 0. Setup

**Accounts.** Gmail aliases all land in one inbox but count as separate La Persona users.

| Who   | Email                | Role in these tests                  |
| ----- | -------------------- | ------------------------------------ |
| **N** | `you+new@gmail.com`  | brand-new user, never signed in      |
| **U** | `you+user@gmail.com` | existing user without platform admin |
| **T** | your Thakhin admin   | platform admin                       |

**Signing in** (used by every part below):

1. Go to `/sign-in`, enter the email, click **Send Magic Link**.
2. Open the "Your LA PERSONA magic sign-in link" email and open its link in the same window.

## Part 1: Signing in

### 1.1 New user signs in (N)

1. Go to `/sign-in`, enter **N**'s email, click **Send Magic Link**.
2. Expected: a "Check your inbox" toast naming the email.
3. Expected: one "Your LA PERSONA magic sign-in link" email arrives for **N**.
4. Open the link.
5. Expected: you land under `/platform`, signed in as **N**, with a personal workspace already created.

### 1.2 Existing user signs in again (U)

1. Sign in as **U**, then sign out (2.1).
2. Sign in as **U** again.
3. Expected: you land under `/platform` in the same personal workspace as before. No second account or workspace is created.

### 1.3 Email validation on the form

1. On `/sign-in`, leave Email empty and click **Send Magic Link**.
2. Expected: an "Email required" toast, and no email is sent.
3. Enter `not-an-email` and click **Send Magic Link**.
4. Expected: an "Invalid email" toast, and no email is sent.

### 1.4 A magic link works only once

1. Request a link for **U** and open it. Expected: signed in.
2. Sign out, then open the same link again.
3. Expected: you are sent back to `/sign-in` and stay signed out.

### 1.5 A tampered link fails

1. Request a link for **U**, change a few characters of `token=` in the URL, and open it.
2. Expected: you are sent back to `/sign-in` and stay signed out.

### 1.6 Return to the page you came from

1. Signed out, go to `/platform/contacts`.
2. Expected: you are redirected to `/sign-in?redirectTo=/platform/contacts`.
3. Sign in as **U** from that page.
4. Expected: after opening the link you end up on `/platform/contacts`.

### 1.7 External redirects are ignored

1. Signed out, go to `/sign-in?redirectTo=https://example.com`, and sign in as **U**.
2. Expected: you land under `/platform`, never on `example.com`.

### 1.8 Signed-in users skip the sign-in page

1. Signed in as **U**, go to `/sign-in`.
2. Expected: you are redirected to `/platform`.

## Part 2: Signing out

### 2.1 Log out (U)

1. Signed in as **U**, open the user menu and click **Log out**.
2. Expected: you are on `/sign-in`.
3. Go to `/platform`.
4. Expected: you are redirected to `/sign-in`.

## Part 3: Access boundaries

### 3.1 Signed-out visitors

1. Signed out, go to `/platform`. Expected: redirected to `/sign-in?redirectTo=/platform`.
2. Signed out, go to `/thakhin`. Expected: redirected to `/sign-in?redirectTo=/thakhin`.
3. Signed out, call `GET /api/me/organizations`. Expected: `401`.
4. Signed out, call `GET /api/admin/overview`. Expected: `404`.

### 3.2 Non-admin user (U)

1. Signed in as **U**, go to `/thakhin`.
2. Expected: redirected to `/sign-in?redirectTo=/thakhin`, which then sends a signed-in user on to `/platform`. The Thakhin back office is never shown.
3. Call `GET /api/admin/overview`. Expected: `404`, so the API doesn't reveal that the admin area exists.

### 3.3 Platform admin (T)

1. Signed in as **T**, go to `/thakhin`.
2. Expected: the Thakhin back office loads.
3. Call `GET /api/admin/overview`. Expected: `200`.

## Not covered by e2e

Check these by hand when auth changes:

- Links expire after 30 minutes.
- Google and LinkedIn sign-in (real OAuth providers can't run in CI).
- Sign-in rate limits (`/api/auth/sign-in/**` in `nuxt.config.ts`, and 30 links per minute in the magic-link plugin).

## Notes for e2e tests

- **Email** goes to Mailpit (`SMTP_URL` in `.env.test`), never Resend. Tests read the link with `readMagicLink(email)` from `tests/support/mailpit.ts`. Watch the inbox at `http://localhost:8025` during a run with `KEEP_SERVICES=1`.
- **Accounts:** each test signs in with its own unique address (`auth-<random>@test.local`), so tests never depend on each other or on test order.
- **T** has no fixed account: the test signs up a fresh user and sets `user.role = 'admin'` in the test database.
- **Wait for hydration** before clicking. A click on server-rendered HTML before Vue hydrates does nothing.
- "No email is sent" (1.3) is asserted by checking Mailpit has no message for that address.
